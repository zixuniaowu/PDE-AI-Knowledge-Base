## この領域で作るもの（製品とユーザー）

- **ユーザー**: 授業教材・研修資料を作る教師・研修担当（教材 1 本に数時間〜数日。レベル別バリエーションまで手が回らない）
- **製品**: 学習目標を入力 → 構成案 3 案 → 確定 → 本文ドラフト（基礎/標準/発展）→ 演習問題 + 解説 → 編集して書き出し
- **FDE の設計判断**: 一括生成にしない。**段階ごとに教師が確定して進む**（[プロンプト連鎖](/patterns/prompt-chaining)を UI のステップとして実装）

## 領域の制約と守るべき線

- 専門用語には初出で説明を付ける（製品のテンプレートに組み込む）
- 断定的・誇張表現（「必ず」「最強」）は教育文書として不適切 → **禁止語ガードレール**を実装
- 医学・法律など専門領域の教材は、専門家確認のステップを出力に明記させる

## 製品の中核機能とプロンプト

段階 1〜3 をステップ UI で回す。各段階のプロンプト例:

```text
（構成段階）学習目標: {入力}。対象: 中学 3 年生。
構成案を 3 案出してください。各案は「導入 → 説明 → 演習」の流れで、各セクションの目的を 1 行で添える。

（本文段階）構成案 ② で本文ドラフトを作ってください。
条件: 専門用語は初出時に説明を添える。比喩を 1 つ以上入れる。1 セクション 400 字以内。

（演習段階）本文に対応する演習問題を易/中/難の 3 問と解説付きで作ってください。
問題は本文の知識で解けること。誘導文に答えを含まないこと。
```

## 失敗パターンと設計での対策

| 失敗 | 製品設計での対策 |
|---|---|
| 一括生成で構成が破綻 | ステップ UI（構成確定 → 本文）を強制。前段の確定なしに次へ進めない |
| もっともらしい誤った説明 | 出力に「要確認マーカー」機能（教師が確認済みにした箇所に ✓ を付ける）。未確認のまま書き出し可能だがマーカー数が表示される |
| 汎用の例で刺さらない | 事例差し替え用のエディタブロックを明示。AI 例をそのまま使う箇所と教師記入箇所を色分け |
| 演習問題が本文の写像だけ | 演習生成プロンプトに「本文の知識を**新しい状況**に適用する問題」を必須条件として指定 |

## 技術構成の目安

- スタック: Next.js + DB（教材・学習目標テンプレート）/ AI API（段階呼び出し）
- パターン: プロンプト連鎖（ステップ UI）+ ガードレール（禁止語・用語説明の自動チェック）
- 書き出し: Markdown / Google Docs 連携があると採用が変わる

## 効果の測定

| 指標 | 手作業 | 製品目標 |
|---|---|---|
| 教材 1 本の作成時間 | 3〜5 時間 | 1 時間以内 |
| 演習問題の適切さ（教師評価） | — | 採用率 60% 以上 |
| 学習者の分かりやすさ評価 | ベースライン | 維持以上（速さで質を落とさない） |

## 法規・保存・正本・決裁

- 根拠法規: 著作権法（教材への引用・転載の範囲）。文科省生成 AI ガイドラインの教材作成に関する項
- 保存期間: 教材は次年度再利用前提で版管理。更新日と作成者を必ず記録
- 正本システム: 教材の正本は教材ライブラリ（共有ドライブ等）。AI ドラフトは編集前の作業物
- 決裁者: 教育内容の妥当性は担当教師・教科主任が確認・承認

コストの試算方法は[コスト見積もり](/references/cost-estimate.md)を参照。
