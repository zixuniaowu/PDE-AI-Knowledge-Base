## 背景

定型実装・テストコードは時間がかかるが創造性は低い。逆に、設計判断は創造的だが AI に任せられない。この非対称を利用する。

## 人間の役割

- 設計判断・アーキテクチャ決定
- 生成コードの理解と採否。**理解できないコードはマージしない**
- 境界条件・セキュリティ（認証・認可・入力検証）の実装と確認

## AI の役割

- 関数・モジュール単位の実装たたき台生成
- テストケース一覧（境界値・異常系）とテストコードの生成
- 型・規約に沿った修正案の提示
- 既存コードベースを踏まえた実装箇所の提案（RAG）

## プロンプト例

```text
あなたはこのリポジトリの実装補助です。以下の仕様を実装してください。
条件:
・既存のヘルパー関数を再利用する（新規に作る前に src/utils を検索）
・テストコードも生成する（正常系2、境界値2、異常系2）
・出力は {files: [{path, code}], tests: [{name, code}], assumptions: []} 形式
・判断に迷った点は assumptions に列挙し、勝手に決めない
仕様: （記入） 関連設計書: （添付）
```

## 失敗パターン

- 存在しない API・ライブラリ関数を生成する → バージョンを固定して伝え、利用 API の実在を CI で保証
- テストが「常に通る空テスト」になる → アサーションの存在をコードレビューで必ず確認
- 巨大 diff でレビュー不能になる → 関数単位で小さく依頼し、PR も小さく切る

## 効果の測り方

- 定型実装の工数（導入前後比較）
- 生成コードの採用率・修正量
- 不具合率が上がっていないか（リリース後の欠陥数）
