## 目標

選んだ 1 プロダクトについて、**自分が決めること**と**AI に任せること**の線を明示的に引く。PDE は分業を一人に収めるが、すべてを AI に任せるのではない。むしろ AI が速く生成できる時代だからこそ、**判断（何を作るか・どこが良いか・出すか出さないか）に自分の時間を全振りする**のが PDE の立ち位置である。

## 線引き表の作り方

仕事を「生成 / 判断 / 外に出さない」の 3 分類に振る:

| 分類 | 内容 | 例 |
|---|---|---|
| **AI に任せる（生成）** | たたき台・大量処理・定型 | 初期コード、テスト雛形、文案の複数案、データの分類 |
| **自分でやる（判断）** | 選択・評価・責任 | 課題の選定、デザインの取捨、コードの採否、リリース判断 |
| **外に出さない（禁止）** | 機密・個人情報 | 実名データ、API 鍵、他人の情報 |

PDE が陥る最大の罠は「生成の速さに引きずられて判断をサボる」こと。**生成は AI、判断は自分**——この線を一日の中で何度も引き直す感覚が PDE の筋肉になる。

## ツールの組み合わせの例

| 局面 | ツール候補 | 自分が残す判断 |
|---|---|---|
| プロトタイプ | v0 / Figma Make | どの案を採るか、状態遷移の追加 |
| 実装 | Claude Code / Cursor | アーキテクチャ、依存の承認、コードの最終確認 |
| 文案 | Claude / GPT | トーンの最終判断、事実確認 |
| 検証 | Claude（分析） / Lighthouse | 何を直すか、リリース可否 |

## やることリスト

- [ ] 自分の作業を「生成 / 判断 / 禁止」に分けた表を作る
- [ ] ツールの組み合わせを 1 行で決める（例: 設計は v0、実装は Claude Code）
- [ ] 「自分が必ずやること」を 3 つ書いて目につく場所に貼る（例: 課題選定 / 依存承認 / リリース判断）
- [ ] 機密情報の扱いルールを決める（[機密情報の持ち込みルール](/patterns/confidential-inputs)）
