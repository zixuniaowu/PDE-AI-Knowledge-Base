## 目標

その業務を**誰がやっても同じ品質**にできるよう、プロンプトと受け渡しの型をファイルに残すこと。

## プロンプトの型: 4 つの部品

良いプロンプトは毎回ゼロから書かず、型の部品を差し替えるだけにします。

| 部品 | 内容 | 例 |
|---|---|---|
| **役割** | AI に何の専門家として振る舞ってほしいか | 「あなたは高校数学の採点補助です」 |
| **入力** | 何を読ませるか（フォーム・添付・参照） | ルーブリック + 答案 |
| **指示** | 出力の形式・範囲・制約 | 「点数は出さず、達成度と根拠の引用まで」 |
| **出力の型** | 期待する構造 | 「設問ごとに箇条書き 3 項目」 |

特に重要なのが**制約**です。「〜しないで」という否定形の制約（例: 点数を提案しない、否定語で始めない）が品質を大きく左右します。

## 受け渡しの設計

協働は「1 回のプロンプト」ではなく**ループ**です。

```
人間: 入力を渡す → AI: 下書き → 人間: 指摘・修正 → AI: 反映 → 人間: 検収
```

- どこで人間が手を入れるか（チェックポイント）を明示する
- AI の出力をそのまま外に出さない。**必ず人間の検収ステップを 1 つ入れる**
- やり取りが 3 往復を超えるようなら、入力か指示の型に問題があることが多い

## やることリスト

- [ ] プロンプトの型をファイルとして保存（チームで共有できる場所に）
- [ ] チェックポイント（人間が手を入れる場所）を明記
- [ ] 実際に 3 回以上回して、型を微調整する

実例は各[ユースケース](/domains)の「プロンプト例」セクションにあります。
