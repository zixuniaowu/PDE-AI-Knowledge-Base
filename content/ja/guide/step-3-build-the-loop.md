## 目標

AI とのやり取りを**毎回ゼロから**やめる。PDE の日々は「依頼 → 検証 → 修正」のループでできており、このループの型を持っている人が速度を出せる。

## 基本のループ

```
依頼（型に従って） → AI が生成 → 自分が検証（AI 評 + 自分の目） → 修正依頼 or 採用
```

### 依頼の型: 4 部品

| 部品 | 例 |
|---|---|
| **役割** | 「あなたはこのリポジトリの実装補助です」 |
| **入力** | 設計の状態一覧 / データ / 既存コードの該当箇所 |
| **指示** | 「①〜③の状態を実装。テストは境界値を含める」 |
| **制約** | 「新規依存は提案のみ」「仕様にない判断は assumptions へ」 |

**制約（やらないこと）が一番効く。** 「点数は出さない」「設計の好みの指摘はしない」——否定形の制約を書く習慣が品質を分ける。

### 検証の型: 2 段階

1. **AI に自己レビューさせる**: 「この diff をシニアエンジニアとしてレビューせよ」
2. **自分の目で最終確認**: 理解できない行は通さない。説明を求めても理解できないなら採用しない

**PDE の品質は、検証にかけた時間に比例する。** 生成 20 分・検証 80 分でも遅くない。手戻りの方が遥かに遅い。

## プロンプトを資産にする

うまくいった依頼は「型」として保存する。変数だけ替えて再利用する:

```text
（保存例: 画面実装の型）
あなたはこのリポジトリの実装補助です。
【機能】{ここ}
【状態】{状態一覧を貼る}
【条件】Next.js 14 App Router / 既存コンポーネント再利用 / 新規依存は提案のみ
【出力】{files, tests, assumptions} 形式
【改訂メモ】0913: 状態一覧を渡すようにしたら手戻りが激減
```

20 の型が使える PDE と、毎回ゼロから書く PDE では、月の産出量が変わる。型のライブラリは [小技集](/references/prompt-tips) から始められる。

## やることリスト

- [ ] 依頼の 4 部品（役割 / 入力 / 指示 / 制約）で今日の作業を 1 回やってみる
- [ ] 検証を 2 段階（AI 評 → 自分の目）で回す
- [ ] うまく行った依頼を 1 つ「型」としてファイルに保存する
