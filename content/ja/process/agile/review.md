## この工程の目的

スプリント終わりのレビューは、チームでは「ステークホルダーへのデモ」。FDE では**「実際のユーザーに触ってもらい、価値が生まれたかを確認する時間」**である。AI にコードレビューさせた後、この工程で初めて「作ったもの」ではなく「届いた体験」を見る。ここを省略すると、FDE は"速く作れるが誰の役にも立たないものを作る人"になる。

- **インプット**: リリース済みの増分、テスターからの反応、利用データ、ゴールの一文
- **アウトプット**: 価値の判定（達成 / 未達成とその理由）、次スプリントへの持ち込みリスト、テスターへの感謝と共有
- **FDE 版の時間感覚**: スプリント末の 1 時間。デモを見せる 15 分 + 反応を聞く 30 分 + 自分でまとめる 15 分

## よくある失敗

1. **デモの成功だけを見る**: 自分で操作するデモは必ず成功する。ユーザーに触らせる
2. **「いいね」を価値の証拠にする**: 「便利そう」は価値ではない。「毎日使っている」「同僚にも共有した」が証拠
3. **悪いニュースを拾わない**: 使われた画面・使われない機能を見る勇気。利用データは容赦ない
4. **AI の称賛をレビューと勘違いする**: 「素晴らしいプロダクトですね」はレビューではない

## FDEの仕事

- **テスターに触ってもらう**: 自分は黙って観察。どこで迷い、どこで無言になるかを記録する
- **価値の判定**: ゴール一文に照らして「達成 / 未達成」を自分で判定する。未達成なら、何が足りなかったか
- **次への持ち込み決定**: 反応から出た改善案を、バックログに「価値の仮説」付きで戻す
- **テスターへの還元**: 反応を共有し、次の版にも関わってもらう。テスターは資産

## AIツールの使いどころ

| 局面 | ツール | 使い方 |
|---|---|---|
| レビューの設計 | Claude / GPT | テスターへのタスク依頼文・観察記録テンプレートの準備 |
| 反応の整理 | Claude / GPT | テスターの声を「価値の証拠 / 改善点 / 意見」に分類（証拠の判定は自分） |
| 利用データの解釈 | Claude (Analytics 貼付) | 使われた画面・使われない機能、完走率の読み取り仮説 |
| 判定の壁打ち | Claude / GPT | ゴール一文と事実を渡し、「達成判定が甘くないか」を反対側から指摘させる |

## 進め方（実プロンプト付き）

### テスターへの依頼（触ってもらう前）

```text
ユーザーテストの依頼文を作ってください。
タスク: 「録音をアップロードして議事録を作り、共有リンクを同僚に送る」
条件: ・操作の手順は教えない（アプリの中身だけで完走してもらう）
・つまずいたら「そこで何を期待したか」を声に出してもらう
・終了後に聞く質問: ①どこが一番不安でしたか ②このまま使いたいと思いますか ③誰に勧めますか（いなかったら素直に言ってください）
```

### レビュー後のまとめ

```text
テスター 5 名の結果を貼ります。次の形式で整理してください。
①ゴール判定の材料: 完走 5 名中何名 / かかった時間 / つまずきの分布
②価値の証拠: 継続利用・共有したなどの行動事実（「便利そう」は証拠にしない）
③持ち込み候補: 改善案（価値の仮説 1 行 + 完成の定義案）
※判定は私がします。
```

### 自分への反対尋問

```text
私の達成判定を攻撃してください。
ゴール: 〇〇 / 私の判定: 達成（理由: 〇〇）
・判定が甘い可能性（証拠の弱さ、テスターの選び方の偏り）
・「達成」だが実は価値がない可能性
・反証となるデータの見方
```

## 成果物と受け入れ基準

- 価値判定（達成 / 未達成 + 理由）、テスターの声の整理、持ち込みリスト

受け入れ基準:

- [ ] 実ユーザーに触れてもらった（自分のデモだけではない）
- [ ] 価値の証拠が行動事実ベース（継続利用・共有・推薦など）
- [ ] ゴールに対する判定が自分の言葉で下されている
- [ ] 持ち込み候補には「価値の仮説」が付いている
- [ ] テスターに結果を還元した

## 前後の工程との接続

- **プランニング ←（逆方向）**: 未達成なら、原因は「作ったもの」か「ゴールの設定」かを切り分けて次スプリントへ。どちらも正常なループ
- **バックログへ**: 持ち込みリストはリファインメントの入力。価値の仮説がないものは入れない

## 顧客案件での追加事項（FDE 差分）

- **スプリントレビュー = 顧客デモ**: 実際の業務担当者に触ってもらい、**検収署名**につなげる。デモは本物データで
- **範囲交渉の場**: レビューで出た追加要望は、スコープ内か外かをその場で分類して記録する
- **請求・検収の接続**: レビューの記録がそのまま月次請求・検収書の根拠になる
